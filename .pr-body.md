## Why this slice

Phase 1 of the Sedea extension platform requires a canonical **GitHub template repository** before scaffold, MCP store, or install missions can reference a stable source. This PR publishes `sedea-extensions/extension-template` v0.1 — the smallest standalone artifact for user bespoke extensions, mergeable without sedea center or Mission Control host changes.

Plan: `.sedea/operations/.../plans/1_extension_template_repo_d69ce521.plan.md` (parent phase: `1_template_and_platform_docs_d0457dab`).

## What changed

- **GitHub template repo shell** — TypeScript VS Code extension scaffold with `compile` / `lint` / `typecheck` / `test` / `verify` scripts and Vitest unit test.
- **CI** — `.github/workflows/ci.yml` runs `npm run verify` on push/PR.
- **`AGENTS.md`** — EDH smoke steps, extension MCP contribution manifest guidance, Sedea MCP Hub external-only boundary (extension-native MCP via install mission, not Hub UI).
- **MCP appendix assets** — `sedea.mcp-contribution.example.json` + `sedea.mcp-contribution.schema.json` documenting v0.1 manifest shape for `extensionContributions` at install time.
- **Template metadata** — repository marked as GitHub template (`isTemplate: true`).

## Not in this PR

- Webview UI shell (optional follow-up).
- Runtime MCP server implementation (manifest documentation only).
- Sedea app monorepo wiring (`@sedea/extension-shared`, native extension symlinks).
- sedea center **`maintain extension template`** mission (PR 2 in phase plan).
- Platform routing docs (PR 3 in phase plan).

## Intentional non-changes

- **Publisher id** remains `your-publisher-id` placeholder — scaffold mission replaces on materialize.
- **No `@sedea/extension-shared` dependency** — external user repos must not depend on app monorepo packages.

## How to verify

npm ci && npm run verify
